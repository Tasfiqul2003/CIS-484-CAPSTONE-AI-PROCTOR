# Oral exam captions, heard text and early ending — November17,2026

User requested a small list of recognized speech, renamed it to **What the examiner heard**, requested toggleable captions independent of FlashHead generation, and requested an **End exam** button in the Question and answer section. All edits remain local and uncommitted.

## Visible behavior

- The automatic oral examiner now shows a small **What the examiner heard** panel. It lists the last6 recognized turns with question number and neutral processing/request status, including spoken repeat/clarification/move-on requests and unclear responses. Silence/empty recognition is explicitly labeled as no transcript. Text appears after a listening turn is transcribed, not word-by-word while the microphone is recording. This uses the actual machine draft sent to examiner processing; it does not pretend speech recognition is exact.
- This panel is page memory only and resets on a new session. It does not write transcript history into browser storage or change submitted answers, scores or recording provenance. The latest entry scrolls into view. Existing cancellation checks reject late results.
- A **Captions on/off** toggle controls a separate HTML overlay over the examiner stage. Caption text appears during actual playback. Native placeholder speech uses the utterance text; optional avatar playback uses corresponding clip text. This is not rendered into FlashHead frames and needs no FlashHead changes or extra model requests. Turning captions off hides the speech text rather than leaving a duplicate caption below the stage. State/status messages and the separate recognized-speech panel remain.
- Captions default on. Only the on/off preference is stored locally; toggling never restarts playback/listening or advances the exam. The toggle supports keyboard focus and aria-pressed state.
- **End exam** appears in the Question and answer footer and during automatic oral mode. It opens a native modal confirmation with Continue exam as the initial focus. The message says submitted answers and the available recording are saved, an unfinished spoken/typed answer is not submitted, and the attempt cannot resume. The exam continues until confirmation.
- After confirmation, new oral capture/submissions stop. The authenticated server ending request is idempotent; it preserves the pending question as unanswered, records a low-severity student-ended boundary, and applies existing identity-review/terminal status rules. Then the existing recording flush/finalization runs. Request timeout/lost response can be retried without submitting the unfinished answer. Upload/finalization failures retain existing recording recovery controls. Professor review and final grading rules remain unchanged.
